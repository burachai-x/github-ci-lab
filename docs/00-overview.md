# 00 — CI ฝั่งตรวจโค้ดคืออะไร และทำไมต้องมี

## CI ไม่ได้แปลว่า "รัน test"

Continuous Integration คือข้อตกลงว่า **ทุกการเปลี่ยนแปลงต้องถูกตรวจด้วยเกณฑ์ชุดเดียวกัน โดยอัตโนมัติ ก่อนรวมเข้า `main`**
การรัน unit test เป็นแค่หนึ่งในเกณฑ์นั้น ในโลกจริงเกณฑ์ยังรวมถึง

- โค้ดฟอร์แมตตรงกันทั้งทีมไหม (ไม่งั้น diff จะเต็มไปด้วยการขยับวรรค)
- มีค่าลับหลุดเข้า git ไหม
- โค้ดที่เพิ่งเขียนมีช่องโหว่ที่รู้จักกันดีไหม
- ไลบรารีที่ใช้มี CVE ค้างอยู่ไหม
- image ที่จะ deploy มีช่องโหว่ไหม

## ทำไมต้องทำใน CI ไม่ใช่ให้คนรีวิวจับเอง

คนรีวิวเก่งเรื่อง "ตรรกะธุรกิจถูกไหม" แต่ไม่เก่งเรื่อง "มี key หลุดใน commit ที่ 7 จาก 41 commit ไหม"
งานที่ซ้ำ ๆ แม่นยำ และน่าเบื่อ คือหน้าที่ของเครื่อง ส่วนคนควรได้เอาเวลาไปคิดเรื่องที่เครื่องคิดแทนไม่ได้

## ต้นทุนของการเจอช้า

| เจอตอนไหน | ต้นทุนโดยประมาณ |
|-----------|------------------|
| ตอนพิมพ์โค้ดในเครื่อง | นาทีเดียว แก้จบ |
| ตอน CI รันใน PR | สิบนาที เพิ่มอีก commit |
| ตอนรีวิวโดยคน | เป็นชั่วโมง ต้องสลับ context กลับมา |
| หลัง deploy ขึ้น production | เป็นวัน + ต้องแจ้งลูกค้า + อาจต้องหมุนค่าลับใหม่ทั้งระบบ |

นี่คือที่มาของคำว่า **shift left** — ดันการตรวจไปทางซ้ายสุดของเส้นเวลาให้มากที่สุด

## แล้ว CD ล่ะ

repo นี้จงใจ**ไม่**แตะเรื่อง deploy เพราะอยากให้โฟกัสอยู่ที่ฝั่งตรวจโค้ดก่อน
เมื่อทีมคุ้นกับด่านพวกนี้แล้ว การต่อ CD เข้าไปท้าย pipeline จะเป็นเรื่องง่ายกว่ามาก
เพราะของที่จะถูก deploy ผ่านการตรวจมาครบแล้ว

## ลำดับที่แนะนำให้เปิดใช้ในโปรเจกต์จริง

1. **Code Quality + test** — ไม่มีใครเถียง และทำให้ทีมคุ้นกับการที่ CI แดง
2. **Secret Scanning** — ผลตอบแทนสูงสุดต่อแรงที่ลง ตั้ง 10 นาทีแต่กันเรื่องใหญ่ได้
3. **SCA** — เปิด Dependabot ก่อนเลย ได้ของฟรีแทบไม่ต้องคอนฟิก
4. **SAST** — เริ่มจากกฎชุดเล็กที่แม่น อย่าเปิดทุกกฎวันแรกเพราะ false positive จะทำให้ทีมเลิกเชื่อ
5. **Container Scanning** — เมื่อเริ่ม deploy ด้วย image

## กติกาสำคัญ: อย่าทำให้ CI แดงจนคนชิน

pipeline ที่แดงตลอดเวลาเป็นอันตรายกว่าไม่มี pipeline เพราะทีมจะเรียนรู้ที่จะเพิกเฉย
เพราะฉะนั้นต้องแยกให้ชัดระหว่าง

- **บล็อก (blocking)** — ของที่รับไม่ได้จริง ๆ เช่น secret หลุด, ช่องโหว่ระดับ critical, ฟอร์แมตผิด
- **รายงาน (non-blocking)** — ของที่ควรรู้แต่ยังไม่ต้องหยุดทุกอย่าง เช่น CVE ระดับ medium ที่ยังไม่มีแพตช์

ใน repo นี้แต่ละ workflow จะระบุไว้ชัดว่าตัวเองอยู่ฝั่งไหน
